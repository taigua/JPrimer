# 显式-隐式转换器

有一个原语可以自动将单行显式定义转换为等效的隐式定义。通过编写一行显式定义，将它们转换为隐式形式，
并研究得到的隐式定义，逆可以学到很多关于隐式编程的知识。

我们用华氏度的显示定义来试一下。`:`的左参数3创建显式定义。`:`的左参数13创建隐式定义。

```j
   fx =:  3 : '32 + y * 9 % 5'	NB.  3 explicit
   ft =: 13 : '32 + y * 9 % 5'	NB. 13 tacit
```

使用**Edit | Session Display Form | Linear**显示。

```j
   ft
32 + 1.8 * ]
```

乍一看，这是令人困惑的，因为它一次引入了几个新东西。首先要做的是查看盒装显示。

使用**Edit | Session Display Form | Boxed**选择盒装显示。

```j
   ft
+--+-+---------+
|32|+|+---+-+-+|
|  | ||1.8|*|]||
|  | |+---+-+-+|
+--+-+---------+
```

在盒装的顶层有3个盒子。这是一个有三个要素的序列：noun verb verb。序列**noun verb verb**当作**noun"_ verb verb**，
这是一个分叉。你可以把它拆开，给各个部分命名，然后分开看。

分叉的第一个元素是短语`32"_`。给它起个名字，试着把它当作一个单子动词。

```j
   left =: 32"_
   left 123
32
   left i.5
32
```

不管你给`left`什么参数，它都会返回32。你以前见过连词`"`，但不是带常数左参数。
我们在[NuVoc](https://code.jsoftware.com/wiki/NuVoc)里查一下。当你翻到定义`"`的秩信息时，
你会注意到定义有三页，每页都是单独页面。这三页是：

```j
	Rank	u " n
	Rank	m " n
	Assign rank	m " v	u " v	mv lv rv
```

不同的定义是用于不同类型参数的秩连词。在标题中，`m`和`n`表示名词参数，`u`和`v`表示动词参数。
你之前使用的`"`包含一个动词左参数和一个名词右参数涵盖在第一个定义中。`32`和`_ (infinity)`都是名词，
所以和第二个定义相关。

阅读`m"n`的定义可以清楚地看出观察结果是正确的。派生动词的右秩为`_`，应用于它的整个右参数，
且无论右参数是什么，都会返回左参数，即`32`。

让我们看看分叉的右参数。

```j
   right =: 1.8 * ]
   right 23
41.4
   right 10
18
```

让我们不要担心定义的细节，而是再一次通过观察，动词`right`所做的是将其参数乘以`1.8`（即`9%5`）。

最后一个定义是个分叉。

```j
   ff =: left + right
   ff 100
212
   ff 0
32
```

比较上一课中的手动隐式定义与自动翻译的隐式定义，并注意它们的不同之处。

```j
32&+@(1.8&*)
32+1.8*]
```

隐式编程丰富多样，与`bond`、`atop`、`rank`等副词和连词以及`hook`、`fork`等序列紧密相连。
