# 隐式定义

动词摄氏度通过连词`:`被显式定义。术语**显式**表示定义中动词的参数通过其名称x和y显式地引用。

在隐式定义中，参数没有名字，也不显式地出现在定义中。参数由定义的语法要求隐式引用。你已经使用了几个隐式定义。

```j
   plus =. +
   sumover =. +/
   maxover =. >./
   scale =. % >./
   mean =. +/ % #
```

以上都是隐式定义。并且不要通过名称来引用参数。在某些情况下，隐式定义比同等的显式定义更简单、更明显。
在更复杂的情况下，你可能需要一些经验才能适应一个隐式定义。这部分是因为你可能有显式定义的经验，
而很少有隐式定义的经验。此外，隐式定义往往是定义的更简洁和数学表达形式。在等效的隐式定义变得清晰之前，
可能需要经历更详细的创建显式定义的步骤。

让我们回顾一下华氏度，看看它是如何被隐式定义的。打开`cf.ijs`脚本，查看华氏度定义。

```j
fahrenheit =: 3 : 0
t1 =. y * 9
t2 =. t1 % 5
t3 =. t2 + 32
)
```

你可以从清理显式定义开始。现在你对J比较熟悉了，你可以将这些计算合并成一行。

```j
fa =: 3 : '(y * 9 % 5) + 32'
```

括号是必需的，因为其中的计算必须在加32之前完成。

让我们稍微调整一下定义，使构建隐式定义的步骤更清晰一些。

```j
fb =: 3 : '32 + ((9%5) * y)'
```

上面的代码可以理解为：**将32加到参数的九分之五上**。

所以，你需要一个`add32`动词和一个`ninefifthtimes`动词。你可以用绑定连词`&`来隐式构建这些动词。
带有常量左参数的绑定连词返回一个派生单子，该单子是带有常量左参数并需要右参数的动词。

```j
   add32 =: 32 & +
```

这将`add32`定义为将32与其参数相加的单子。

```j
   add32 12
44
   ninefifthstimes =: (9%5) & *
```

这给出了一个单子，它把其参数乘以9%5。

```
   ninefifthstimes 20
36
```

结合这些，你会得到：

```j
   add32 ninefifthstimes 100
212
```

连词`@`将两个动词组合成一个派生动词，该派生动词将右边的动词应用于其参数，然后将左边的动词应用于该结果。

```j
	(u @ v) y	evaluates as	u v y
```

使用连词`@`将两个动词组合起来，形成最终的定义。

```j
   fc =: add32 @ ninefifthstimes
   fc 100
212
   fc _40
_40
   fc 0
32
```

显示动词fc，并注意其定义依赖于其他两个定义。

```j
   fc
+-----+-----------------+
|add32|@|ninefifthstimes|
+-----+-----------------+
```

有时，在你从较小的构建块构建了一个隐式定义之后，你会意识到真的不希望所有这些较小的定义到处存在。
副词`f.`以一个隐式定义为参数，并将其中的名字替换成对应的定义。

```j
   fz =. fc f.
```

副词`f.`像所有副词一样，其参数在它的左边。

看一下`fz`的最终定义。

```j
   fz
+--------+-+---------+
|+--+-+-+|@|+---+-+-+|
||32|&|+|| ||1.8|&|*||
|+--+-+-+| |+---+-+-+|
+--------+-+---------+
```

系统可以以几种不同的形式显示隐式定义。这些选项可以通过**Edit | Session Display Form | Boxed**来选择，
你将得到上面的显示。**盒装**在理解隐式定义方面非常有用。不过，现在选择**Linear**，这样你会看到以下内容：

```j
   fz
32&+@(1.8&*)
```

在比较像定义为`+`的动词这样简单的东西时，隐式定义要比等效的显式定义简单得多。在华氏度的例子中，
可以认为显式定义更简单，特别是如果你直接使用`1.8`而不是像默认定义那样使用`9%5`。

```j
fx =: 3 : '32+1.8*y'
vs.
fz =: 32&+@(1.8&*)
```

隐式编程的真正优势在于对参数进行更复杂的转换，特别是当参数必须被多次引用时。下面举例说明了隐式定义的另一种用法。

```j
   xmean =: 3 : '(+/y) % #y'
```

这是你们在[分叉](./093.md)章节遇到的平均值。

```j
   mean =: +/ % #
```

隐式定义只是直接使用分叉。

分叉也可以在显式定义中使用，但需要在分叉周围加上括号。

```j
   xmean =: 3 : '(+/ % #)y'
```

隐式定义的一个优点是，与显式定义相比，它们更容易以正式的方式进行操作。例如，
J可以自动派生许多隐式定义的逆定义。让我们用隐式定义`fz`尝试一下。华氏度的逆是摄氏度的数。
标准配置文件定义了副词`inverse`。

```j
   fz =: 32&+@(1.8&*)
   cz =: fz inverse
   fz 100
212
   cz 212
100
   fz 0
32
   cz 32
0
```

隐式编程非常强大，但没有必要深入它。重要的知道它是什么，并在简单的情况下开始使用它，
因为这是熟悉它的最好方法。
