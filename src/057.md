# 容差

这一部分有点高级，理解它并不重要。如果能理解，那很好。如果不明白，不要担心，直接进入下一部分。

对于使用浮点数的某些工作，本节非常重要，同时还需要更详细地了解硬件如何存储和操作数值。然而，对于大多数工作，这部分可以忽略。

在上一节的最后，我们看到计算机不能总是精确地表示数值。那么如果它们不能被精确地表示出来呢，我们怎么知道一个数是否等于另一个数？
解决这个问题的方法是宽容比较的概念。也就是说，数值不必完全相同才能被认为是相等的。

让我们通过实验来了解比较的宽容度如何，方法是逐渐使值远离100。使用输入行召回快捷键`Shift+Ctrl+Up`对于这类操作非常有用。
```j
   100 = 100
1
   100 = 99.999999999999986
1
   100 = 99.99999999999998
1
   100 = 99.9999999999999
1
   100 = 99.999999999999
1
   100 = 99.99999999999
0
```

在上面的示例中，你越过了这条线，使得数值离100足够远，以至于它们不再被认为是相等的。让我们看另一个例子。
```j
   a =. 23
   b =. a - 1e_12
   c =. a - 1e_11
   a
23
   a-b
9.9831254374294076115e_13
   a=b
1
   a-c
1.0000889005823410116e_11
   a=c
0
```

a和b的值足够接近，可以认为是相等的。a和c的值不够接近，不能认为是相等的。
足够接近和两个数值之间的差异相关。在这两种情况下，差异都很小，但b比c更接近a。
阅读[NuVoc对=定义](https://code.jsoftware.com/wiki/Vocabulary/eq#dyadic)，
你将看到足够接近和不够接近之间的分界线是由较大的数值乘以默认容差值`2^_44`的结果决定的。
也就是说，足够接近与否与数值的大小有关。

将两个差异值和容差值进行比较：
```j
   (a - b , c) <: tolerance    NB. Remember, this is equivalent to (a - (b,c)) due to right to left precedence.
1 0
```

a和b之间的差异小于或等于容差，而a和c之间的差异则不是。
